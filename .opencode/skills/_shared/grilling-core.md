# Grilling with docs: shared protocol

Следуй этому протоколу вместе с профильным skill.

## Веди grilling

1. Сначала извлеки факты из кода, catalog, CI, docs и исполняемых контрактов. Не спрашивай то, что можно надёжно вывести.
2. Разделяй `fact`, `decision`, `assumption`, `unknown`. Для факта храни evidence; для решения — альтернативы и последствия.
3. Задавай за ход 1–3 связанных вопроса. Сначала закрывай то, что меняет архитектуру, объём или приёмку.
4. На размытый ответ запроси пример, границу, контрпример или критерий проверки.
5. Выявляй противоречия между ответами, evidence и моделью. Покажи конфликт кратко и добейся одного решения.
6. После существенного ответа обнови модель и unknowns; не создавай документ на каждую реплику.

## Храни только полезное

- Исполняемый процесс — в Nix, а не Markdown.
- Принятое долгоживущее решение — ADR по `templates/decision.md`.
- Значимый доменный термин — в `docs/glossary/` по `templates/glossary-term.md`.
- Хак или долг — в атомарной заметке.
- Стенограмму, непринятые альтернативы и внутренние рассуждения не сохраняй.

Не дублируй факт между catalog, plan и docs: выбери источник истины, из остальных сошлись на него.

## Завершай по доказательству

1. Сформулируй outcome, non-goals и наблюдаемые acceptance criteria.
2. Укажи evidence для каждого критичного факта.
3. Перечисли unresolved unknowns и их влияние; не маскируй их предположениями.
4. Проверь артефакты и связи профильными validators.
