# Правила ревью проекта

- Проверь критерии приёмки, границы задачи, совместимость изменённых API и взаимодействие всех затронутых репозиториев.
- Ищи конкретные ошибки с условием воспроизведения и последствием. Укажи repository, path, reason, fix и severity для каждого finding.
- Безопасность: валидация внешних данных; path traversal и symlink; командные/SQL-инъекции; утечки секретов в ответах и логах; права доступа; небезопасная десериализация; обработка ошибок и недоверенных файлов.
- Для CSV проверь пустые данные, отсутствующие колонки, неверные типы, кодировку и ошибки чтения. Новая функциональность должна иметь проверки граничных случаев.
- Не выполняй код. Используй исходники, diff, доказательства контроллера и результаты обязательных checks. Недостающие доказательства укажи явно.
- Не требуй стилистических правок, уже покрытых форматтером, без отдельного правила или объяснимой ошибки.
- База знаний может содержать устаревшие сведения; предложения её обновления необязательны для приёмки кода. Не изменяй базу сам.
- Итог передай один раз через `review_submit`. После успешной отправки дай короткое подтверждение.
