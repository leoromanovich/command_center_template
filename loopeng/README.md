# Command Center · Pi + Docker

Переносимый CC с циклом разработки:

```text
Planner (+ Jira при настройке) → одобрение плана
  → Builder (+ Explorer) → formatter → lint / tests → Reviewer
    ↑__________________ исправления __________________|
  → пользователь: diff / обратная связь / приёмка
  → публикация commit / push / MR по выбранному действию
  → необязательное обновление базы знаний после отдельного одобрения
```

Корень этого репозитория — ваш Command Center. Пайплайн полностью находится внутри него. Для реальных агентов задана `zai/glm-5.3-flash`. Авторизация берётся из установленного Pi на этой машине.

## Первый запуск

Нужны Node **≥22.19**, Pi **0.79.9 или 0.85.1**, Git, Docker с локальным Linux daemon. Для просмотра diff — Vim/Neovim. Пайплайн использует Node built-ins и SDK установленного Pi; `npm install` внутри CC не требуется. Если Pi отсутствует, установите проверенную версию: `npm install -g @earendil-works/pi-coding-agent@0.85.1`.

Свежий checkout содержит **пустой рабочий CC**. `./start` покажет инструкцию подключения репозиториев. Заполните `repositories` и команды проверок в `cc.config.json` или `cc.local.json`, опишите проекты в `docs/repositories.md`, добавьте toolchain в `docker/Dockerfile`. Форма настроек — `examples/cc.local.example.json`; подробности — [CONFIGURATION.md](docs/CONFIGURATION.md).

После настройки:

```sh
./cc build-image
./cc doctor
./start
```

`build-image` собирает образ рабочего проекта; исходный `docker/Dockerfile` содержит минимальную среду с Python для файловых инструментов контейнера. Первоначальная сборка требует сети. Собственные formatter/linter/test-команды и их зависимости задаются для каждого проекта.

## Отдельный CSV-пример

```sh
./cc build-image --example
./cc example
```

Если образ `local/cc-sandbox-python:0.1` уже установлен, первая команда не нужна. `example` создаёт и открывает `.local/examples/python-catalog/CommandCenter` с GLM. У него собственные репозиторий, профиль, знания, проверки, worktree, задачи, диалоги и статистика. Runtime используется общий. [Подробности и пробная задача](examples/python-catalog/README.md).

`./cc init-example` только подготавливает этот отдельный CC. Повторный вызов сохраняет его файлы и историю. Для продолжения: `./cc example --resume`. Основной профиль при этом не меняется.

Planner задаст уточнения и подготовит worktree. Откройте `/tasks`, выберите задачу и посмотрите план (`p`). `a` одобряет подготовленный план и запускает цикл. Новые задачи создавайте через `/plan-new` или новый запуск `./start`.

Для демонстрации без токенов: `./cc demo`. Напишите «Подготовь демо», затем одобрите план в `/tasks`. Этот фиксированный сценарий использует настоящий Pi SDK и Docker, проходит три круга с ошибкой линтера и замечанием Reviewer. Для собственных задач служит обычный `./start`.

## Во время работы

- `/tasks` или `/cc` — задачи, агенты и запросы пользователя; общий статус виден под чатом.
- `/cc-stats` — токены и стоимость всего CC; `/cc-stats <task-id>` — одной задачи. `t` в списке задач открывает статистику CC, в карточке — выбранной задачи. Русская `е` тоже работает.
- В карточке задачи справа сразу виден живой вывод активного агента: сообщения и рассуждения оформлены как в Pi, инструменты показывают аргументы и результат. Панель сама переключается между работниками; выбор строки конкретного агента показывает его историю.
- Колесо над live-панелью прокручивает её и передаёт ей фокус. Клик внутри панели или `Tab` тоже переключает фокус; затем работают `j/k`, `gg/G`. `l` возвращает слежение, `o` раскрывает полный вывод инструментов. `w` открывает просмотр на весь экран, `q` возвращает. При ширине меньше 110 колонок `Tab` сразу открывает полный экран. Клик слева возвращает управление меню.
- Выберите проверки или Docker и нажмите Enter для живого stdout или истории контейнерных команд. Запросы пользователя доступны через `e` в карточке, включая фокус live-панели.
- «Обсудить с Orchestrator» возвращает в чат с контекстом выбранной задачи.
- `s` останавливает работу; `a` продолжает сохранённый цикл.
- `r` открывает результат после завершения цикла; `e` открывает diff в Vim/Neovim. `:q` возвращает в Pi.
- На экране результата: `a` принимает код; `f` отправляет замечания Builder.
- После приёмки: `u` — публикация, `m` — сообщение коммита, `1/2/3` — commit/push/MR, Enter — выполнить показанное действие. По умолчанию доступен локальный commit; push выключен.
- `b` — предложения для базы знаний, если настроен её сабмодуль.
- `j/k`, `gg/G`, `q`, остальные буквенные клавиши работают и в русской раскладке. Подсказки зависят от текущего экрана.

Запрос команды показывает её cwd и назначение. Одобренная пользовательская команда выполняется на хосте в нужном каталоге; stdout и результат сохраняются автоматически. Это отдельный переход через границу контейнера.

## Возвращение к работе

```sh
./start --resume
# или конкретный диалог:
./start --session SESSION_ID
```

Обычный `./start` открывает новый чат. История задач доступна через `/tasks` во всех чатах этого CC. Фоновый контроллер сохраняет стадию, сессии работников и результаты проверок. После обрыва откройте задачу и продолжите её. Если исход команды неизвестен, сначала проверьте её результат; UI покажет требуемое действие.

## Что менять под свой проект

| Файл | Назначение |
|---|---|
| `cc.config.json` | Общие модели, репозитории, проверки, Git-политика, Docker |
| `cc.local.json` | Необязательные настройки этой машины; исключён из Git |
| `model-prices.json` | Ручные цены моделей за миллион токенов: префилл, генерация, чтение/запись кэша |
| `docs/repositories.md` | Карта репозиториев, связи, сборка, правила выбора веток |
| `rules/review.md` | Правила Reviewer, включая безопасность |
| `checks/` | Доверенные проверки, замораживаемые при подготовке задачи |
| `docker/Dockerfile` | Базовый образ Builder; рядом пример для C++ |
| `runtime/pi/` | Pi extension, работники, интерфейс и их тесты |
| `runtime/core/` | Контроллер цикла, Git, Docker, восстановление, журнал |
| `examples/python-catalog/` | Исходники отдельного учебного CC; в рабочий профиль не включены |

Настройка: [CONFIGURATION.md](docs/CONFIGURATION.md). Статистика и цены: [STATISTICS.md](docs/STATISTICS.md). Изоляция и сборки: [DOCKER.md](docs/DOCKER.md). База знаний: [KNOWLEDGE.md](docs/KNOWLEDGE.md). Архитектура, логи и разработка: [PIPELINE.md](docs/PIPELINE.md).

Git хранит исходники пайплайна и общий профиль с моделями. `.pi/` (диалоги, планы, логи, одобрения, сгенерированный профиль), `.local/`, `wt/`, `cc.local.json` игнорируются. Ключи Pi остаются в пользовательской конфигурации. Для переноса истории нужен отдельный локальный backup этих папок; обычный clone переносит шаблон. Активные задачи содержат абсолютные пути: перенос checkout с ними требует отдельной миграции.

Remote репозитория задаётся владельцем. Подключение реальных Git/Jira/MR сервисов описано в конфигурации; фиктивные remotes и учётные данные в шаблон не включены.
