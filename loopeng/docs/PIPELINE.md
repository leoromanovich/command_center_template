# Устройство и сопровождение

`scripts/cc.mjs` формирует профиль относительно checkout. `runtime/pi/extension.mjs` регистрирует команды и инструменты, отображает задачи. `runtime/pi/worker.mjs` запускает SDK-сессию конкретной роли. `runtime/core/lib/controller.mjs` управляет стадиями, снимками, обязательными проверками и ревью. `background.mjs` запускает отдельный процесс контроллера; `recovery.mjs` хранит leases/идентичности процессов и восстанавливает выполнение.

Реальные модели заданы в `cc.config.json`. Тестовый `cc-demo/scripted` только воспроизводит сценарии; это отдельная тестовая конфигурация. Тесты не вызывают GLM.

## Логи

В `.pi/cc-state/<task>/`:

- `commands.log`, `commands.jsonl` — команды, cwd, роль, exit code, длительность и Docker argv;
- `events.jsonl`, `state.json` — переходы стадий и текущее состояние;
- `pi-events/*.jsonl` — видимый поток агента, инструменты и usage;
- `pi-sessions/` — SDK-сессии для продолжения;
- `docker-logs/`, `docker-activity/` — stdout/stderr и контейнеры;
- `checks.json`, `*-check-*.log` — проверки;
- `knowledge-update/` — отдельное состояние необязательного KB-этапа.

Диалоги Planner/Orchestrator: `.pi/sessions/`. Планы: `.pi/cc-plans/`. UI показывает опубликованное моделью thinking и события инструментов в пределах доступного от провайдера потока.

В карточке задачи `lib/live-view.mjs` отображает тот же `pi-events` поток в правой панели через компоненты сообщений Pi. Обновление — каждые 750 мс; чтение ограничено последними 128 KiB каждого потока. Полная история остаётся в JSONL. Несколько фрагментов ответа и результаты одного вызова инструмента объединяются. По умолчанию длинный вывод инструмента сокращён до последних 12 строк; `o` раскрывает доступный вывод. Прокрутка останавливает автослежение, `l` возобновляет его. Панель не открывает дополнительную SDK-сессию и не отправляет запросы модели.

Клик и колесо переключают клавиатурный фокус на соответствующую панель. В fullscreen используется `handleMouse` Pi. В regular `lib/pointer.mjs` включает SGR-события только на время открытого CC, учитывает границы overlay и отключает захват при закрытии или запуске редактора/команды в терминале. Клики выбирают строки; выполнение действий по-прежнему требует клавиатурного подтверждения.

Сохраняйте `.pi/`, `.local/`, wt и исходные Git-репозитории вместе для локального backup. Worktree и task snapshots содержат абсолютные пути. Свежий clone шаблона создаёт новое окружение, историю задач переносите отдельно с проверкой путей.

## Проверки самого пайплайна

```sh
npm test
npm run test:core
npm run test:docker
```

Для Pi-тестов нужен установленный поддерживаемый Pi. Docker-тестам нужен запущенный daemon и `local/cc-sandbox-python:0.1`. Сценарии создают временные собственные репозитории, проходят цикл, проверяют восстановление, RO/RW-права и публикацию в локальные тестовые remotes. Продакшен-репозитории и модельные API не используются.

В `tests/template.test.mjs` проверяется переносимость чистого checkout, пустой рабочий профиль, приоритет конфигов, независимая история примера, повторная инициализация, поиск Planner и Git-ignore. `tests/docker.test.mjs` проверяет отдельный CSV-профиль, Ruff и acceptance внутри настоящего Docker.

Рабочий CC находится в корне checkout. Материалы CSV-примера хранятся в `examples/python-catalog/`; явный `./cc example` создаёт его CC в `.local/examples/python-catalog/CommandCenter`. Задачи и расходы каждого CC собираются только из его собственных каталогов. Старые `.local/repositories/catalog`, wt и `.pi` автоматически не переносятся и не удаляются. Ранее выполненные в рабочем CC задачи остаются в его истории; новая структура не переписывает прошлую статистику.

## Происхождение исходников

Это самостоятельный снимок созданного ранее пайплайна. Pi-адаптер перенесён из `pi-command-center`, ядро — из `opencode-example/opencode`, seed/образы — из `docker-sandbox`. Пути импорта перенастроены на локальный `runtime/core`; исходные папки проекта остаются самостоятельными. Изначальный список файлов и хеши — `runtime/import-manifest.json`.

Дальнейшие изменения этого CC ведите здесь. Автоматической синхронизации с прежними папками нет. В ядре сохранены общие модули и тестовый OpenCode-адаптер для регрессий; установленный OpenCode для запуска Pi-пайплайна не требуется. Сторонний SDK Pi не скопирован: используется установленный пакет указанной версии.

Шаблон намеренно хранит весь runtime в одном Git-репозитории: версии UI, контроллера, конфигов и проверок изменяются вместе. Перед обновлением runtime остановите активные jobs и сохраните локальное состояние.
