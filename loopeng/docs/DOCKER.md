# Образ и изоляция

`docker/Dockerfile` — минимальная основа Python 3.12 Alpine. Python нужен файловому helper независимо от языка проекта. Добавьте свои toolchain и зависимости. Pi/Node и модель работают на хосте; контейнеру нужен `python` ≥3.9, инструменты проекта и shell. `./cc build-image` собирает Dockerfile с тегом из `sandbox.image` (по умолчанию `local/cc-builder:0.1`).

Отдельный CSV-пример использует `examples/python-catalog/docker/Dockerfile` с закреплённым Ruff и тег `local/cc-sandbox-python:0.1`. Его сборка: `./cc build-image --example`. Настройки рабочего профиля на неё не влияют.

Для C++ используйте `docker/Dockerfile.cpp` как основу: добавьте свой toolchain, зависимости и заранее собранные библиотеки в `/opt/deps`. Затем измените основной Dockerfile и команды checks. Этот тяжёлый пример автоматически не собирается. Зафиксируйте версии зависимостей, ABI и базовый digest под вашу платформу.

Контекст `docker build` — соответствующий каталог `docker/` рабочего CC или примера. Если нужны подготовленные SDK, поместите их в него и настройте `.dockerignore`/COPY. Большие локальные артефакты добавьте в `.gitignore` либо получайте при сборке по закреплённым версиям.

## Mounts

| Путь | Доступ |
|---|---|
| `/workspace/<repo>` | Feature worktree; RW у Builder/formatter, RO у Reviewer/Explorer/остальных checks |
| `/workspace/<repo>/.git` | Пустая RO-подстановка; общая Git-база скрыта |
| `/context` | RO-снимок файлов `sandbox.contextFiles` |
| `/knowledge` | При подключении базы: RO; выбранные файлы изменяются только после одобрения KB-этапа |
| `/build`, `/home/agent` | Хранилище роли; сохраняется между её командами |
| `/tmp` | Временная файловая система текущего контейнера |

Контейнер: non-root uid/gid пользователя хоста, сеть выключена, rootfs RO, `cap-drop=ALL`, `no-new-privileges`. Docker socket, SSH-agent, пользовательский home и ключи модели не монтируются. Git и пользовательские команды на хосте выполняются через доверенный контроллер.

При prepare фиксируются image ID и контекст, создаётся retention tag. Пересборка тега сохраняет прежний образ для уже подготовленных задач. Автоскачивание образа при выполнении выключено. Слои образа переиспользуются. Удаляйте retention tags только после завершения соответствующих задач.

Каждая команда получает новый контейнер. Build/home сохраняются по роли; checks одной попытки разделяют свой `/build`, следующая попытка начинает с чистого каталога. Между задачами build-кэш сейчас автоматически не разделяется. C++-сборку направляйте в `/build`, поскольку tests/typecheck работают с RO-исходниками.

Дополнительные произвольные host mounts пока отсутствуют. Статические зависимости включайте в образ; небольшие текстовые правила — в `contextFiles`. База знаний подключается поддерживаемым отдельным сабмодулем. Весь CC внутрь контейнера не монтируется.

Фоновые процессы завершаются вместе с командой. Проверку HTTP-сервера делайте одним вызовом: старт, запросы, остановка. Длительно живущий сервис между вызовами пока не поддерживается.

Используется локальный Docker daemon с теми же bind mount путями. На Docker Desktop каталог CC должен быть доступен для file sharing. Изоляция зависит от Docker/ядра и доверенного образа; лимиты CPU/RAM в этом шаблоне не задаются.
