# База знаний как Git-сабмодуль

Подключение выполняется один раз из корня CC:

```sh
git submodule add <URL-вашей-базы> knowledge
git add .gitmodules knowledge
git commit -m "Connect project knowledge"
```

После clone используйте `git submodule update --init`. Сабмодуль должен быть чистым и находиться на SHA, закреплённом текущим коммитом CC.

Добавьте в `cc.config.json`:

```json
{
  "knowledgeBase": {
    "submodule": "knowledge",
    "writablePaths": ["docs"],
    "checks": [["python", "-I", "/context/checks/knowledge.py", "/knowledge/docs"]],
    "remote": "origin",
    "ccRemote": "origin"
  }
}
```

Каталог `docs` должен существовать в базе. Замените его своими каталогами. Пример проверяет заголовок, завершающую новую строку и отсутствие NUL в Markdown. `checks: []` оставляет только встроенные проверки допустимых файлов. Для запуска этой проверки добавьте `checks/knowledge.py` в `sandbox.contextFiles`; универсальный скрипт лежит в CC, по умолчанию он не монтируется.

Во время реализации Builder читает закреплённую базу в `/knowledge`, предлагает обновления через `kb_propose`. Предложения не блокируют приёмку и публикацию кода.

После приёмки откройте задачу → `b`, выберите предложения клавишами `1`–`9`, нажмите Enter. Запустится тот же Builder в отдельной сессии: принятый код RO, разрешена запись только в явно выбранные страницы базы. Shell, Git и Explorer на этом этапе отсутствуют.

Результат: `e` — diff в Vim/Neovim, `f` — исправления, `u` — публикация. Контроллер создаёт commit базы и отдельную ветку CC с обновлённым gitlink. Основной checkout CC и сабмодуля сохраняется. Push идёт в порядке KB → CC и требует `git.allowPush=true`. После локального commit push можно выполнить позже. MR/merge этих веток пока выполняются отдельно.

Если обновление базы сломалось, принятый код остаётся принятым. Снимок принятого кода исключает ignored build-файлы; ошибка его создания может потребовать повтор (`c` на экране базы). Вложенные Git-сабмодули внутри реализации требуют отдельной схемы профилей и сейчас не поддерживаются этим снимком.

Перед новым планированием обновите ветку CC и gitlink обычным командным процессом. Автоматического rebase одобренных KB-изменений на новую ревизию нет.
