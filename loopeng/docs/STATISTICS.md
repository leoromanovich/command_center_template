# Токены и стоимость

В Pi:

- `/cc-stats` — весь Command Center;
- `/cc-stats <task-id>` — конкретная задача;
- `t` в списке `/tasks` — весь CC;
- `t` или пункт «Статистика · токены и стоимость» в карточке — выбранная задача.

Клавиша `t` работает также как `е` в русской раскладке. Навигация: `j/k`, `gg/G`, PageUp/PageDown; `q` возвращает на предыдущий экран. Открытие статистики сохраняет текущую роль и ничего не запускает/одобряет. Данные обновляются примерно раз в секунду после сохранения ответа.

## Что считается

| Поле | Значение |
|---|---|
| `input` | Префилл без чтения и записи кэша, в нормализованном usage Pi |
| `output` | Генерация; включает reasoning, если провайдер учитывает его здесь |
| `cacheRead` | Входные токены, прочитанные из кэша |
| `cacheWrite` | Входные токены, записанные в кэш |

Итого = сумма четырёх полей. Весь обработанный вход = input + cacheRead + cacheWrite. `reasoning` и `cacheWrite1h` являются подмножествами output/cacheWrite и повторно не прибавляются. Счётчики берутся из usage провайдера через Pi; размер контекста и локальная токенизация для оценки расхода не используются.

Есть разбивки по моделям, агентам и задачам. Включаются Builder, Reviewer, Explorer, execution-reviewer, Builder этапа базы (`builder · KB`), Planner и Orchestrator. Учитываются сохранённые usage компактации и branch-summary, включая историю до сжатия контекста. У custom summary от стороннего extension модель может быть неизвестна; её токены видны, тариф остаётся неопределённым.

Все повторные вызовы и неуспешные ответы с сохранённым usage входят в расход. Продолжение сессии и повторное открытие статистики не добавляют расход. Общие записи, скопированные при fork сессии, учитываются один раз. `toolResult.usage` не суммируется: дочерние модельные запросы учитываются по собственным сессиям, иначе возможен двойной счёт.

## Привязка планирования

До создания задачи диалог Planner виден как **CC · без привязки к задаче**. После успешного `cc_prepare` предыдущие ещё непривязанные ответы текущей ветки планирования и последующий разговор относятся к этой задаче.

Переход «Обсудить с Orchestrator» привязывает последующие ответы. Сам просмотр чужой карточки не переносит туда прежние расходы. Если общий участок планирования участвует в fork, он относится к первой задаче, которая его привязала. Общий итог CC содержит его один раз.

Старые диалоги используют уже сохранённые `cc-state` привязки для последующих ответов. Их раннее планирование без нового маркера остаётся в общей непривязанной строке. История соседних CC автоматически не импортируется.

## Ручные тарифы

Путь задаётся `pi.pricingFile` в профиле; в шаблоне это `model-prices.json` в корне CC. Файл перечитывается при обновлении статистики. Перезапуск Pi, prepare и новое одобрение задачи для изменения цен не требуются.

Для `zai/glm-5.3-flash` настроены обычные API-тарифы Z.ai, проверенные 2026-09-24: input $0.15, output $0.50, cacheRead $0.03 за миллион токенов. Источник: [официальная таблица цен](https://docs.z.ai/guides/overview/pricing).

Отдельный тариф записи кэша не опубликован, поэтому `cacheWrite` оставлен `null`. Бесплатное хранение кэша в таблице Z.ai — отдельная характеристика. [Документация кэширования](https://docs.z.ai/guides/capabilities/cache) описывает новые входные токены по обычной ставке и попадания в кэш по сниженной. Текущий ответ Z.ai не выделяет токены записи; Pi сохраняет `cacheWrite: 0`, что позволяет полностью рассчитать стоимость по трём заданным ставкам. Если ненулевой счётчик записи появится, стоимость будет отмечена как неполная до задания тарифа.

Формат файла; тарифы `other-provider/other-model` ниже **условные**:

```json
{
  "currency": "USD",
  "models": {
    "zai/glm-5.3-flash": {
      "input": 0.15,
      "output": 0.50,
      "cacheRead": 0.03,
      "cacheWrite": null
    },
    "other-provider/other-model": {
      "input": 3.0,
      "output": 9.0,
      "cacheRead": null,
      "cacheWrite": null
    }
  }
}
```

Цены — **за 1 000 000 токенов**, в одной валюте `currency`. Название модели должно точно совпадать с `provider/model` в отчёте. Другой provider с таким же названием модели получает свой тариф. Отсутствующее поле или `null` означает неизвестную цену, `0` — явную бесплатную ставку.

Формула: `(input × inputRate + output × outputRate + cacheRead × cacheReadRate + cacheWrite × cacheWriteRate) / 1 000 000`.

Если для потраченных токенов нет ставки, показываются известная часть стоимости и количество токенов без тарифа. Полный итог в JSON будет `null`. Некорректный файл цен выдаёт предупреждение, счётчики токенов сохраняются. Встроенные оценки `usage.cost` из Pi не подменяют ручные тарифы.

Общий файл цен хранится в Git. Для индивидуальных цен создайте `model-prices.local.json` (он игнорируется) и укажите в `cc.local.json`:

```json
{ "pi": { "pricingFile": "model-prices.local.json" } }
```

Изменение пути подхватывается новым запуском Pi; содержимое файла подхватывается открытым экраном статистики.

Оценка всей истории пересчитывается по текущему файлу цен. Исторические версии тарифов, налоги, скидки и конвертация валют пока отсутствуют. Стоимость отражает сохранённые usage.

## Источники и экспорт

Читаются полные `.pi/sessions/*.jsonl` и `<stateRoot>/<task>/pi-sessions/**`, включая `knowledge-update/pi-sessions/**`. Tail-ограничения просмотра логов здесь не применяются. Сессии остаются первичным источником; статистика не меняет их и не создаёт второй журнал расходов. В памяти сохраняются поля учёта, тексты диалога в экспорт не входят.

```sh
./cc stats
./cc stats my-task
./cc stats --json
./cc stats my-task --json
```

JSON содержит общие и групповые счётчики, текущие тарифы, известную стоимость, `cost: null` при неполной оценке и предупреждения. Команда работает без запуска модели и Docker.

Если usage отсутствует, запись отмечается как неполная. Оборванный запрос, для которого провайдер не вернул usage или Pi не успел сохранить ответ, оценить нельзя. Неполная последняя строка дописывающегося файла будет прочитана при следующем обновлении; повреждённые строки пропускаются с предупреждением. Удаление исходных сессий удаляет их вклад из статистики, поэтому сохраняйте `.pi/` вместе с резервной копией CC.
