# Отдельный CSV Command Center

Это учебный CC для самостоятельных задач с GLM-5.3-Flash. Его файлы создаются только при явном запуске примера.

Из корня шаблона:

```sh
./cc build-image --example
./cc example
```

Сборку можно пропустить, если образ `local/cc-sandbox-python:0.1` уже установлен. Для подготовки без запуска Pi: `./cc init-example`. Для возвращения к диалогу: `./cc example --resume` или `./cc example --session <id>`.

Рабочие каталоги:

```text
.local/examples/python-catalog/
  repositories/catalog/       исходный Git-репозиторий
  CommandCenter/
    start                     launcher общего runtime
    AGENTS.md, docs/, rules/  знания и правила примера
    checks/                   Ruff и frozen acceptance
    model-prices.json         собственные тарифы
    .pi/cc-profile.json        профиль примера
    .pi/cc-plans/              планы
    .pi/cc-state/              задачи, usage и логи работников
    .pi/sessions/              диалоги Planner/Orchestrator
    wt/<task>/catalog/        реализация
```

У рабочего CC в корне шаблона свои `.pi/`, wt, профиль и статистика. Генератор примера не меняет их. `.local/` игнорируется Git.

Пробная задача:

> Добавь category_counts(items), возвращающую количество записей по категориям. Проверь пустой список и несколько категорий. Сохрани read_items. Работаем от main, commit/push пока выключены. Сначала обсудим план.

После планирования: `/tasks` → задача → `p` → `a`. После цикла откройте diff, примите результат или верните замечания. `/cc-stats` показывает расход только этого CC; `t` / русская `е` открывает статистику в списке и карточке.

Повторный запуск сохраняет рабочие файлы, настройки и историю. Изменения в исходном шаблоне этого каталога применяются к новым экземплярам; существующий профиль редактируется в `CommandCenter/.pi/cc-profile.json`. Тарифы копируются при создании, дальше редактируются отдельно. При незавершённой инициализации генератор сохраняет файлы и сообщает путь для проверки.

`./cc demo` — отдельный фиксированный сценарий без модельных API-вызовов. Его состояние остаётся в `runtime/pi/.docker-demo/`; запуск CSV-примера использует настоящую GLM и расходует токены.
